실전 4단계
한 달에 하나씩 — 4개월이면 완성
1
코드 전에 계획 먼저
1달차 · 매 작업 시작 전 · 바로 지금 시작 가능
기본 — 계획 요청
이 기능 구현하기 전에 어떻게 고칠 건지 계획부터 정리해줘. 코드 짜기 전에 수정 대상 파일과 로직 흐름 먼저.
스펙 검토 강제화
작업 시작 전 체크: 1. 수정할 파일 목록 2. 변경 로직 한 줄 요약 3. 예상 엣지케이스 이 세 가지 먼저 정리하고 내 승인 받아.
마이그레이션 작업 전
마이그레이션 시작 전, 1) 어떤 파일을 어떤 순서로 건드릴지 2) 각 단계 완료 기준이 뭔지 3) 롤백 기준은 뭔지 계획서 한 페이지로 작성해줘.
2
자주 하는 일 → 스킬로 문서화
2달차 · 같은 일 3번 이상 반복될 때
스킬 초안 작성 요청
내가 자주 하는 이 리팩토링 패턴을 재사용 가능한 스킬 문서로 정리해줘. 구성: 언제 쓰는지 / 실행 순서 / 완료 기준.
스킬 업데이트 (실수 후)
방금 이 케이스에서 실수가 나왔어. 이런 경우엔 이렇게 해 라는 줄을 기존 스킬 문서에 추가해줘.
스킬 멀티섹션 구성
이 스킬을 세 섹션으로 나눠줘: 1) 기본 케이스 2) 예외 케이스 3) 검증 체크리스트 각 섹션은 독립적으로 쓸 수 있게.
3
도메인 단위로 코드 묶기
3달차 · 새 기능부터 적용 · 기존 코드는 점진적으로
도메인 폴더 구조 설계
결제 기능을 도메인 폴더로 묶어줘. 한 폴더 안에: 컴포넌트 / 훅 / API / 타입 / 테스트 / 도메인 매뉴얼 다 들어가게 구조 잡아줘.
도메인 매뉴얼 작성
/payment 폴더 안에 DOMAIN.md 만들어줘. 내용: 이 도메인의 규칙, 금지 사항, 새 기능 추가할 때 체크리스트. AI가 이 파일 먼저 읽고 작업 시작하게.
작업 범위 좁히기
이번 작업은 /payment 폴더 안에서만. 다른 폴더 건드리지 말고, DOMAIN.md 먼저 읽은 다음 시작해.
4
자동 검사 설치
4달차 · 작업 완료 후 자동 게이트
자동 검사 파이프라인 요청
작업 끝날 때마다 자동으로 린트 → 빌드 → 테스트 순서로 돌게 pre-commit hook 또는 CI 설정해줘.
빌드 깨졌을 때
빌드 에러 났어. 코드 고치기 전에 에러 메시지 원인부터 분석하고 수정 계획 한 줄로 말해줘.
테스트 커버리지 체크
방금 추가한 기능, 엣지케이스 3가지 이상 테스트 커버됐어? 안 됐으면 지금 추가해줘.

스레드 자동화 SaaS
X(트위터) 스레드 생성 · 예약 발행 서비스
STEP 1 — 계획 먼저
스레드 파싱 + AI 재작성 + 예약 발행 3개를 한꺼번에 짜달라고 했다가 버그 투성이
계획 먼저스펙 리뷰
스레드 자동화 3개 모듈 짜기 전, 각 모듈 수정 파일, 인터페이스, 테스트 기준 계획서로 먼저 정리해줘. 내 승인 후 시작.
STEP 2 — 스킬화
스레드 톤 조절 리팩토링을 매번 다르게 해달라고 하다가 일관성이 없어짐
스킬 문서
스레드 톤 조절 패턴을 스킬로 정리해줘. 섹션: 공격적→부드럽게 / 짧게 압축 / 해시태그 추가 각 섹션 독립적으로 쓸 수 있게.
STEP 4 — 자동 검사
중복 발행 버그가 프로덕션에서 터짐. 검수 없이 바로 배포했던 게 문제
자동 검사멱등성
발행 로직 변경할 때마다 자동으로: 1) 중복 발행 방지 테스트 2) 멱등성 체크 3) 예약 큐 무결성 확인 이 세 개 자동 실행되게 설정해줘.

STEP 3 — 도메인 폴더

STEP 2 — 스킬화

스킬 문서

영상 콘텐츠 자동화
자막 추출 · AI 요약 · 숏폼 스크립트 생성
STEP 1 — 계획 먼저
자막 파싱·요약·숏폼 변환을 한번에 짜달라고 했다가 스파게티 코드 탄생
계획 먼저
영상 파이프라인 4단계 구현 전, 각 단계 입출력 인터페이스와 단계 간 의존성 다이어그램 먼저 그려줘.
STEP 2 — 스킬화
플랫폼별 숏폼 형식이 달라서 매번 다시 설명해야 함 (릴스/틱톡/쇼츠)
스킬 문서
숏폼 스크립트 변환을 스킬로 정리. 플랫폼별 섹션: Instagram Reels / TikTok / YouTube Shorts 각각 길이 제한, 훅 위치, 자막 스타일 기준 포함.
STEP 4 — 자동 검사
메모리 누수가 큰 영상 파일 처리 시 OOM으로 서버 다운
자동 검사메모리
영상 처리 코드 변경 시마다 자동으로: 1) 메모리 누수 테스트 (100MB 이상 파일) 2) 스트림 미종료 체크 3) 임시 파일 정리 확인 이 세 가지 CI에 추가해줘.

도메인 폴더DOMAIN.md

STEP 1 — 계획 먼저
리스크 스코어링 알고리즘 변경할 때마다 기존 판정 결과가 바뀌어서 고객 불만
스펙 먼저
스코어링 로직 변경 전, 변경 영향 받는 조항 카테고리 목록, 기존 결과값 유지 케이스 vs 변경 허용 케이스 명세서로 먼저 정리해줘.
STEP 4 — 자동 검사
실제 계약서 100건으로 테스트 안 하고 배포했다가 오분류 버그 발생
자동 검사회귀 테스트
스코어링 코드 변경 시마다 자동으로: 1) 골든셋 100건 회귀 테스트 2) High 리스크 false negative 0건 확인 3) 처리 속도 SLA (건당 2초 이내) CI 파이프라인에 추가해줘.

STEP 2 — 스킬화
